CampusIQ Documentation

Smart College Management & Analytics Platform

1. Executive Summary

CampusIQ is a comprehensive web-based Smart College Management & Analytics Platform designed to streamline academic operations, enhance student-faculty engagement, and provide data-driven insights for institutional decision-making.

Problem Statement

Educational institutions face challenges in managing student attendance across multiple courses, tracking assignment submissions and grading workflows, generating performance analytics and reports, coordinating department-level academic operations, and maintaining secure access control across different user roles.

Solution

CampusIQ provides a unified platform that addresses these challenges through real-time attendance tracking with predictive analytics, comprehensive assignment management system, automated grade recording and performance tracking, role-based dashboards for different user types, and exportable reports in CSV and PDF formats.

7. Authentication and Security

CampusIQ uses JWT-based authentication with role-based access control enforced on every protected endpoint.

  • Authentication: JWT (Access + Refresh tokens)
  • Password Hashing: bcrypt (primary), argon2 (optional)
  • Token Expiry: 30 min access, 7 day refresh
  • Authorization: RBAC enforced on every endpoint with resource-level scoping

10. Database Design

Core Entities

  • User: id, email, role, status
  • Student: user_id, enrollment_number, department_id, semester_id, section
  • Faculty: user_id, department_id, designation
  • Department: name, code
  • Assignment: title, subject_id, faculty_id, deadline, max_marks
  • Attendance: student_id, date, status

Database Support: SQLite (development), PostgreSQL (production)

11. Frontend Architecture

React 18 with TypeScript using component-based architecture, role-based routing, and React Query for data fetching. Navigation and routes are protected based on user role.

12. Backend Architecture

FastAPI with structured layers: API routes → Dependencies/RBAC → Service layer → Database. SQLAlchemy ORM with Alembic migrations.

18. Known Limitations

  • Rate limiting defaults may need adjustment for high traffic
  • AI integration requires external provider; demo mode available
  • 10MB file upload limit with restricted extensions
  • SQLite lacks production features; PostgreSQL recommended
